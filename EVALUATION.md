# EVALUATION.md

The quality contract for AcquiScout. `PROJECT.md` states the business targets; this file states **how they are measured, where the labels come from, and what blocks a merge**.

If a metric is not defined here, it cannot be claimed in a README, demo, or pitch.

---

## 1. Golden dataset (`golden_v1.json`)

- **Size:** 19 records / 16 unique entities, frozen 2026-11-04 (ADR-026); title + property management, all three counties represented. The 20-entity target moves to `golden_v2`.
- **Build cost:** 3 days of manual research. Not compressible; not generated by the pipeline.
- **Location:** `data/raw/golden_v1.json` (committed, hand-collected).
- **Draft extension:** `data/raw/golden_v2.xlsx` (`2.0-draft`, 42 columns) adds
  `employee_headcount` and `founded_year`. At export, headcount is `NOT_FOUND` on all
  19 rows and founding year is present on 17. Both are context fields; they do not
  enter `human_score_total` or any verdict (ADR-033). v2 is not frozen.
- **In-sample caveat:** the Tier 1/2 search vocabulary was shaped by golden v1
  (ADR-030). Scores against v1 are an upper bound, not a generalization estimate. A
  clean estimate requires a held-out later version.
- **Authority:** This file is a **contract**. Editing it requires:
  1. A version bump (`golden_v2.json`) — never mutate `v1` in place.
  2. A note in `DECISIONS.md` recording why labels changed.
  3. A re-baseline entry in `docs/eval-runs.md`.
- **Labeled fields:**
  - Legal name, DBA, website, county, sector.
  - Revenue band (low/high, USD) and EBITDA band (low/high, USD).
  - Confidence label (`low` | `medium` | `high`).
  - Principals / management-team evidence (source URLs).
  - Contacts with truth labels (`valid` | `stale` | `invalid`).
  - Human acquisition score (0–100) with per-component sub-scores.
  - Human verdict (`qualified` | `semi_qualified` | `rejected`) + rejection reason.
  - Every critical field carries `{value, source_url, retrieved_at, method}`.

- `qualified` — passes G1–G5; matches the brief's "existing management team" and plausible $1.5M+/$500K thresholds.
- `semi_qualified` — passes G1 and G2 but fails G3, or misses one financial gate by no more than 20% with the other gates and G4/G5 passed. It is backlog, not weekly-target qualified.
- `rejected` — fails a financial gate by more than 20%, is out of geographic scope, is a roll-up brand or national subsidiary, or otherwise does not match the brief.

**Evidence rule:** a field without a source URL is not a label — it is an opinion and is excluded from scoring.

## 2. Metrics and thresholds

| Metric | Definition | Threshold | Blocking |
|---|---|---|---|
| EBITDA band alignment | Share of golden companies whose predicted EBITDA band overlaps the human-labeled band | 70–85% | Yes if <70% |
| Revenue band alignment | Same, for revenue | ≥80% | Yes if <80% |
| Score alignment | Share of golden companies with `abs(pred - human) <= 10` | ≥80% | Yes |
| Critical-claim auditability | Share of critical fields (revenue, EBITDA, contact, owner) with source + method + confidence | ≥95% | Yes |
| Contact validity (weekly audit) | Share of sampled contacts that resolve to the labeled person/company | ≥95% | Yes |
| Dedup precision | Share of merged clusters where all members are truly the same entity | ≥95% | Yes |
| Dedup recall | Share of true duplicate pairs that were merged | ≥85% | No |
| Funnel shape | Raw → dedup → scraped → qualified → verified | within ±20% of 500/150/60/25/20 | No |
| Cost per qualified prospect | Total run cost ÷ qualified prospects, measured on a paid-tier reference run | <$5.00 | Paid reference run only |
| Eval suite runtime | Wall clock for full suite | <10 min | No |

"Verified" means source-backed and/or human-audited — never audited financial truth. **EBITDA is always rendered as a proxy with a band.**

### Discovery crawl-worthiness

Discovery is judged on whether it hands the crawl stage fetchable, company-like URLs.
**Golden-set recall is not a discovery metric**; golden labels are used later for
extraction and qualification.

| Metric | Definition | Gate |
|---|---|---:|
| Fetch success | Official-company sample URLs fetched through the crawl stack (Jina Reader, rate-limited to 18 RPM) with ≥400 chars of text | ≥ 90% |
| Crawl-worthy precision | Manual `official_company` labels ÷ web samples | ≥ 80% |
| Non-target share | Directory + government + news + other ÷ web samples | Informational |
| Root-domain diversity | Unique registrable domains ÷ web samples | Informational |

- Sample: `data/raw/discovery_eval_v1.json` (manual labels; registry rows tracked
  separately).
- Only `official_company` samples are fetched, through `Scraper`/Jina; directory,
  government, news, and registry rows are labeled without fetching.
- Runner: `python scripts/eval_discovery.py` writes a timestamped JSON under
  `data/generated/discovery_eval/`.
- Registry candidates are excluded from the web URL precision denominator and reported
  separately; a Sunbiz search-results URL is not a crawl-worthy company page.
- Crawl outcomes (`fetched`, `text_chars`, `extraction_status`) feed back into the
  next discovery eval; they do not retroactively change manual labels.
- Fixed-denominator resolver diagnostic: map every web input to `official` /
  `non_target` / `unresolved` over the fixed denominator (32) and report final unique
  companies separately. An `official` mapping is not a new company; count net-new
  companies and duplicate conversions. Directory resolution is off by default; the
  experiment and decision are in `docs/resolver-experiment.md` (ADR-043).

**Registry evidence metrics:**

| Metric | Definition |
|---|---|
| GovFiles enrichment coverage | registry records with detail fields ÷ registry records |
| Public evidence coverage | registry records with a public Sunbiz/DBPR detail URL ÷ registry records |
| Officer evidence coverage | records with ≥2 named officers on the public page ÷ records |
| Ownership full-credit rate | records eligible for ownership 15 ÷ records |
| Evidence partial rate | search-page-only or failed ÷ registry records |
| Blocked evidence rate | blocked or rate-limited records / registry records |
| Drop-missing-evidence rate | records dropped for missing required public evidence ÷ registry records |
| Company URL resolution rate | high-confidence companies that get an official URL ÷ eligible high-confidence companies |
| Company URL search precision | correct official websites ÷ search-resolved URLs (manual/LLM review) |
| Company URL search cost | Tavily credits per search-resolved URL |

GovFiles detail counts for enrichment only; it never satisfies G3 or ownership evidence.

**Cost during development:** dev runs execute on the free stack (Jina Reader, local Ollama, free-tier Groq/Gemini), so a $0 cost line is a degenerate measurement, not evidence of meeting the target. Dev runs report token counts and free-tier budget consumption. The $5 threshold is measured on a single paid-tier reference run recorded in `docs/eval-runs.md` before the demo (ADR-017).

## 3. LLM-as-a-Judge (alignment only)

- **Role:** the judge compares a generated prospect against the golden label and the rubric. It does **not** produce the pipeline score (see ADR-003).
- **Rubric:** the six weighted components and their anchors in **Scoring rubric (golden labels)** below. The judge compares against those anchors; it does not invent its own.
- **Judge model:** API model (Groq/Gemini), pinned by version string in the run record. Changing the judge model requires a re-baseline.
- **Determinism:** temperature 0, fixed prompt hash. Prompt edits invalidate prior run comparisons.
- **Agreement monitoring:** judge vs human labels on the golden set; report Spearman correlation and mean absolute error per component.
- **Failure mode:** if judge agreement drops below 0.7 Spearman, the judge is considered broken and the eval run is void.

### Scoring rubric (golden labels)

Human labels and the judge share one rubric. Weights are each component's maximum; anchors say how to earn it. Weights live in `ScoreWeights` (`src/acquiscout/schemas.py`); caps and the derived total live in `GoldenRecord` (`src/acquiscout/eval/golden.py`).

| Component | Field | Max |
|---|---|---:|
| Financial fit | `score_financial` | 30 |
| Management | `score_management` | 20 |
| Ownership | `score_ownership` | 15 |
| Contactability | `score_contactability` | 15 |
| Market / strategic | `score_market` | 10 |
| Data confidence | `score_data_confidence` | 10 |

| Component | Full | Partial | Zero |
|---|---|---|---|
| Financial fit | G1 and G2 met, both source URLs, confidence `medium` or `high` → **30** | G1 and G2 met, but confidence `low` or one source URL missing → **15** | Either low band below its gate → **0** |
| Management | Named principal with source **and** a real `management_evidence_url` → **20** | Named principal with source, no team evidence → **10** | No principal or no `principal_source_url` → **0** |
| Ownership | Owner named, registry filing as source, legal form identifiable → **15** | Owner named and sourced, but the registry link is only a search, the form is inferred from the name, or ownership sits behind an entity → **7** | No identifiable owner or source → **0** |
| Contactability | `contact_truth=valid` on a direct owner/principal line → **15** | Sourced, but `stale`, indirect, or of kind `website`/`linkedin` → **7** | `invalid` or no contact source → **0** |
| Market / strategic | HQ in a target county, target sector, and at least one additional county → **10** | HQ in a target county and target sector only → **5** | HQ outside Hillsborough/Pinellas/Pasco, or outside the target sectors → **0** |
| Data confidence | Revenue, EBITDA, contact, and owner each carry source + method + confidence `medium` or `high` → **10** | All four sourced, but at least one is `low` or proxy-derived (`benchmark_ratio`) → **5** | Any of the four lacks a source URL → **0** |

Gates use the conservative low end of each band:

- **G1:** `revenue_low_usd` ≥ 1,500,000
- **G2:** `ebitda_low_usd` ≥ 500,000
- **G3:** `principal_source_url` is a real **public Sunbiz/DBPR detail page** **and** either (a) `management_evidence_url` shows ≥2 named people with roles, or (b) that public registry page lists ≥2 individual officers with titles (ADR-022). GovFiles detail is enrichment only and does not satisfy G3.
- **G4:** headquarters in Hillsborough, Pinellas, or Pasco; `primary_county` records where the mention was observed, not where the company is based
- **G5:** independent operator, not a brand of a multi-brand roll-up or a subsidiary of a larger operator

| Verdict | Rule |
|---|---|
| `qualified` | G1, G2, G3, G4, and G5 |
| `semi_qualified` | G1 and G2, but not G3; **or** exactly one financial gate missed by no more than 20% (revenue ≥ 1,200,000 or EBITDA ≥ 400,000) with the other gates met; in both cases G4 and G5 must hold |
| `rejected` | every other record, including any G4 or G5 failure |

Derivation and clarifications:

- The score ranks prospects; the verdict is decided by the gates. A high score never makes a record qualified.
- `human_score_total` is derived as the sum of the six components. A stored total that disagrees with the sum is an error, and components may not exceed their caps.
- An entity owner (for example, a member LLC) counts as a named principal. With no team page it scores Management 10.
- Size is scored only in Financial Fit; Market / strategic scores geography and sector, never size.
- Any additional county earns Market 10, whether or not it is one of the three target counties. Target county plus sector alone is 5.
- For an out-of-geography entity, `primary_county` is the county where the mention was observed, the HQ county goes in `also_serves_counties`, Market is 0, and the verdict is `rejected` with a reason naming the HQ county (`DECISIONS.md` ADR-024). This overrides the usual Market anchor.
- A brand of a multi-brand roll-up, or a subsidiary of a larger operator, fails G5 and is `rejected` regardless of score; `rejection_reason` names the parent (`DECISIONS.md` ADR-025).
- Ownership full credit requires a **public Sunbiz/DBPR detail/filing page** as the owner source; a company about page, a Sunbiz search-results URL, or a GovFiles-only source scores partial at most. GovFiles detail is enrichment/extraction only and never satisfies ownership evidence.
- Labeler mistakes (typos, arithmetic slips) never move a component; only evidence about the record does.
- Data confidence scores the sourcing of revenue, EBITDA, contact, and owner. Management evidence is scored in Management, not here.

## 4. Regression gate

A change is mergeable only if **all** of the following hold:

1. `python -m pytest -q --tb=short` passes.
2. `ruff check .` and `ruff format --check .` pass.
3. The eval suite runs and every *blocking* threshold in §2 is met.
4. No golden-set label was edited in place.
5. The run record is written to `docs/eval-runs.md` with: commit, judge model, prompt hash, metrics table, cost.

A change touching extraction, estimation, dedup, scoring, or prompts **must** run the eval suite. Docs-only changes may skip it with a note in the PR description.

Until the eval harness exists, discovery/docs changes are gated by `pytest`, `ruff`,
the frozen-v1 check, and a recorded discovery run; no eval score may be claimed.

**Baseline policy:** the first frozen run becomes the baseline. Later runs may not regress a blocking metric by more than 2 percentage points without an explicit ADR.

## 5. Reproducing a run

```powershell
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev,eval]"

# offline wiring only (no network, no keys)
python -m acquiscout.smoke

# golden-set eval (requires keys in .env; tests/eval is not built yet)
python -m pytest -q --tb=short tests/eval
```

CI (GitHub Actions) runs the same commands with secrets injected. Eval artifacts are uploaded as run artifacts; nothing is written back into `data/raw/`.

## 6. What we will not claim

- Any precision/recall figure not produced by the latest recorded eval run.
- That golden v1 scores are out-of-sample performance (see the in-sample caveat).
- That a $5 cost target was met from a free-tier dev run (cost is blocking only on the paid reference run).
- That an EBITDA proxy is an audited number.
- That contacts are "verified" when their status is `unverified` or `single_source`.
- That GovFiles.dev is an approved source for client work; it is a personal-project
  adapter until its ToS and coverage are confirmed (ADR-028).
- That the system replaces financial due diligence or sends outreach.
